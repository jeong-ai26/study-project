## 프로젝트 2: 텍스트 어드벤처 게임 — 설계 스펙

### 파일 구조
```
adventure/
  main.py       # 게임 루프, 입력 처리, 게임오버/승리 판정
  entities.py   # Player, Monster, Item 클래스
  world.py      # 방 데이터 (중첩 딕셔너리) — 코드 없이 데이터만
  combat.py     # 전투 루프 (선택: main.py에 둬도 됨)
```

핵심 원칙 하나: **world.py에는 `if`문이 없어야 합니다.** 데이터만 있고 로직은 main.py에 있는 구조. 이게 지켜지면 방을 추가할 때 코드를 안 고쳐도 되고, 안 지켜지면 지난 가계부처럼 나중에 분리가 "감당이 안 되는" 상태가 됩니다.

### 방 데이터 형태 (world.py)
```python
ROOMS = {
    "entrance": {
        "desc": "...",
        "choices": {"1": ("북쪽 문", "hall"), "2": ("돌아간다", "outside")},
        "item": None,
        "monster": None,
    },
    # ...
}
```
방 6~8개, 그중 몬스터 2~3마리, 아이템 2~3개, 승리 방 1개, 죽음 엔딩 1개 이상.

`choices`의 값이 `(설명, 다음_방_키)` 튜플인 게 상태머신의 전이표입니다. 게임 루프는 `current = ROOMS[current]["choices"][입력][1]` 한 줄로 이동이 끝나야 합니다 — `if 방 == "hall": ...`처럼 방마다 분기하기 시작하면 상태머신이 아니라 그냥 if 덩어리가 됩니다.

### 클래스 설계 (entities.py)

| 클래스 | 상태 | 행동 |
|---|---|---|
| `Player` | `hp`, `max_hp`, `inventory`(list), `location` | `take_damage()`, `heal()`, `add_item()`, `use_item()`, `is_alive()` |
| `Monster` | `name`, `hp`, `attack_power` | `take_damage()`, `is_alive()` |
| `Item` | `name`, `effect_type`, `value` | `apply_to(player)` |

`Player`와 `Monster`에 `hp`/`take_damage()`/`is_alive()`가 겹치는 게 보일 겁니다. **상속은 이 중복을 직접 겪은 뒤에 리팩터링으로** 넣으세요 — 처음부터 `Character` 부모 클래스를 만들면 왜 필요한지 모르는 채로 쓰게 됩니다.

### 단계별 마일스톤
각 단계 끝에 가져오시면 지난번처럼 엄격하게 봐드립니다.

1. **이동만 되는 게임** — world.py + main.py의 while 루프. 클래스, 전투, 아이템 전부 없음. 방 사이를 오가고 잘못된 입력을 걸러내는 것까지.
2. **Player 클래스 + 아이템** — HP, 인벤토리, 방에서 아이템 줍기/사용하기.
3. **Monster + 전투** — 턴제 루프(공격/방어/도망), 전투 후 방 상태 갱신.
4. **엔딩과 마감** — 게임오버/승리 조건, 예외 처리, 반복 코드 정리.

### 지난 프로젝트에서 나온 버그, 이번에 다시 나올 자리
- **순회 중 삭제** — `use_item()`에서 인벤토리를 돌며 아이템을 지울 때 똑같은 인덱스 스킵 버그가 납니다. 원리는 이미 설명받으셨으니 이번엔 미리 피해보세요.
- **EAFP** — 선택지 입력 검증은 `isdigit()` 말고 `ROOMS[...]["choices"]`에 `KeyError`로 접근하는 쪽이 자연스럽습니다.
- **내장 함수명 가림** — `input`, `type`, `next`, `map`이 이번 프로젝트에서 변수명으로 쓰고 싶어지는 이름들입니다.

### 범위 밖 (이번엔 하지 않음)
세이브/로드(JSON), 랜덤/확률, 아이템 조합, 맵 그래픽. 4단계까지 끝나고 여유가 있으면 세이브/로드만 보너스로 붙이세요 — 지난번에 스스로 추론하신 대로 JSON이 맞습니다.
